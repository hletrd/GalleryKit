## Findings

### F1 — DB-restore dangerous-SQL streaming scanner evadable by intra-keyword chunk-boundary split  [SEV: MED | CONF: High | apps/web/src/lib/sql-restore-scan.ts:267-278 + apps/web/src/app/[locale]/admin/db-actions.ts:719-748]

**Problem.** `restoreDatabase` scans the uploaded SQL in 1 MiB chunks (`CHUNK_SIZE = 1024*1024`, db-actions.ts:719). Each chunk is scanned via `appendSqlScanChunk(scanTail, chunk)` → `containsDangerousSql(combined)`. In `appendSqlScanChunk` (sql-restore-scan.ts:272):

```js
const combined = previousTail ? `${previousTail}\n${chunk}` : chunk;
```

The scan is meant to catch a dangerous statement even when it straddles a read boundary, by keeping a compacted 1 MiB tail. But the injected `\n` between the retained tail and the new chunk lands **exactly at the read-buffer boundary**. When an attacker aligns the boundary so it falls *inside a keyword token* (e.g. `DROP TAB`|`LE images;`), the injected `\n` breaks the keyword: the combined string is `...DROP TAB\nLE images;`, and `/\bDROP\s+TABLE\b/i` never matches `TAB\nLE`. The dangerous statement passes the scan and is fed to `mysql --one-database`.

**Why the existing tests miss it.** `sql-restore-scan.test.ts:241-282` cover boundary splits, but every one splits at a **whitespace/word boundary** (`CREATE`|`TRIGGER`, `CREATE`|`FUNCTION`, `DROP`|`DATABASE`). There the injected `\n` lands in the whitespace gap and `\s+` still matches, so those cases are correctly detected. No test splits *inside* a keyword token — that is the uncovered case.

**Failure scenario / evidence.** I reproduced the exact db-actions.ts streaming loop against the real library. `containsDangerousSql('...\nDROP TABLE images;\n')` returns `true` on the whole string, but the chunked stream scan returns **`false`** (evasion) for 7 of 31 boundary alignments of `DROP TABLE images;` — every alignment where the boundary falls inside `TABLE` (pad offsets 990-998 at a 1000-byte chunk; the mechanism is chunk-size-independent, so at the real 1 MiB size the attacker just aligns the statement to offset 1 MiB / 2 MiB / …). Confirmed root cause: a variant that concatenates the tail directly (`tail + chunk`, no injected `\n`) with a raw overlap window drops evasions to 0. The bypass lets a crafted "backup" restore statements the scanner is specifically meant to block: `DROP TABLE` / `DELETE FROM` (data destruction, within the app DB user's own privileges and NOT filtered by `--one-database`), `CREATE TRIGGER … DEFINER=<app_user>` (persistence), and — if the DB user holds the privilege — `INTO OUTFILE` / `SET GLOBAL` / `GRANT`.

**Impact framing.** Defense-in-depth: the restore route is authenticated-admin + same-origin + `--one-database`, and the scanner is the documented protection against a *malicious backup file* being restored by a legitimate admin (untrusted/shared backup, attacker-supplied "restore this" file, or an attacker with write access to the backup source). MED, not HIGH, because the primary auth gate is intact; not LOW, because the scanner is a load-bearing, documented safety control and the bypass is trivially craftable by controlling byte offsets.

**Fix.** The compacted-tail `\n` join is *required* for the huge-whitespace inter-token case (collapsing megabytes of whitespace so `CREATE … TRIGGER` still fits the window), so it cannot simply be removed. Add a **byte-continuous raw overlap bridge** alongside the compacted tail: retain the last N raw bytes of each chunk (N ≥ longest dangerous keyword, e.g. 64) and additionally scan `rawTailSuffix + rawChunkPrefix` with **no separator** so an intra-keyword split is rejoined losslessly. Add a regression test that splits *inside* a keyword (`DROP TAB`|`LE`, `DATABA`|`SE`, `TRIG`|`GER`, `GLOB`|`AL`, `OUTFI`|`LE`) and asserts `true`.

## Verified-hardened (no finding) — surfaces I confirmed carry the right control

- **api-auth `withAdminAuth`** (lib/api-auth.ts): token path rate-limits (`preIncrementAdminTokenAuthAttempt`) BEFORE the DB `verifyToken`, verifies scope via `tokenHasScope`, clears the request-scoped token in `finally`, and defaults `Cache-Control: no-store` + `nosniff` on both token and cookie paths; cookie path enforces `hasTrustedSameOrigin` before `isAdmin()`. `lint:api-auth` passes on HEAD.
- **Admin PATs** (lib/admin-tokens.ts): SHA-256-hashed at rest, constant-time `tokenHashesEqual`, `isWellFormedToken` shape gate before DB, INNER JOIN to `admin_users` (deleted admin ⇒ token cannot authenticate), `expires_at` enforced, plaintext never enters a query parameter.
- **Session/HMAC** (lib/session.ts): HMAC-SHA256 verified with `timingSafeEqual` before shape/age checks (no timing oracle), token hashed for DB storage, `SESSION_SECRET` env required in production (refuses DB fallback), 24h age enforced consistently with cookie `maxAge` and DB `expiresAt`. Login (actions/auth.ts) equalizes Argon2 timing with a module-init dummy hash, per-IP + per-account rate buckets pre-incremented before verify, session-fixation delete-others in one transaction, `secure` cookie via trusted-proxy protocol.
- **Server-action same-origin fence**: every mutating action reads `requireSameOriginAdmin()` and returns early, then `acquireAdminMutationSlot()` restore-fence, then `isAdmin()` (sharing.ts, admin-users.ts, collections.ts, settings.ts, lr-tokens.ts all conform). `deleteAdminUser` serializes last-admin protection under `GET_LOCK`, parameterized raw SQL. `settings.ts` explicitly rejects `semantic_search_mode='production'` from the UI path. `lint:action-origin` passes on HEAD.
- **Path traversal / symlink** (lib/serve-upload.ts, api/admin/db/download/route.ts): `SAFE_SEGMENT` allowlist + `..`/`.` rejection + `lstat` symlink reject + `realpath` containment (`startsWith(root + sep)`) + fd-stat-through-open race safety; dir↔extension map. Backup download `Content-Disposition` filename is constrained by `BACKUP_FILENAME_PATTERN` (no quote/CRLF ⇒ no header injection).
- **OG SSRF** (api/og/photo/[id]/route.tsx, lib/og-photo-fetch.ts): internal derivative fetch pinned to `BASE_URL` origin (never `req.url`), fails closed if canonical URL unparseable, fallback redirect validated same-origin, per-attempt + total fetch budgets, 1 MB byte cap; path component is a DB UUID (no user input). CPU-bound render rate-limited (charged-post-validation).
- **Injection**: CSV export (lib/csv-escape.ts) strips C0/C1 + Unicode bidi/zero-width, collapses CR/LF, formula-prefix guard tolerant of leading whitespace. Admin strings (lib/sanitize.ts, lib/validation.ts) reject bidi/zero-width via shared `UNICODE_FORMAT_CHARS`; `.test()` vs `/g` split correctly avoided. GPS strip (lib/gps-exif-strip.ts) is bounds-checked and fails closed (`null`) on any structural anomaly (incl. `walkAborted`, post-EOI trailer).
- **CSP/headers** (lib/content-security-policy.ts, next.config.ts): prod script-src nonce-only, `frame-ancestors/base-uri/form-action/object-src 'none'`, `/api/*` gets `default-src 'none'; sandbox`, HSTS/XFO/Referrer/Permissions-Policy present, `buildCspSafely` degrades instead of 500ing on malformed `IMAGE_BASE_URL`. (`style-src 'unsafe-inline'` in prod is the already-deferred C2-38.)
- **Rate-limit / IP**: `getClientIp` only trusts XFF under `TRUST_PROXY`, hop-count-indexed, `normalizeIp` validates each hop, 512-byte XFF cap, loud one-time SECURITY warning when proxy headers present without `TRUST_PROXY`.
