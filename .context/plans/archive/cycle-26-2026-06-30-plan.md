Severity/confidence: Warning / High. Attempted fixes this cycle: removed `process.cwd()`/`node:path` from the production marker path during investigation and tried a lazy typed `require('node:fs')`, but ESLint correctly rejected `require()` imports via `@typescript-eslint/no-require-imports`, so the lint-breaking approach was reverted. Deferral reason: the remaining warnings are tied to required runtime filesystem I/O for the durable marker and cannot be removed cleanly without changing the restore coordination design. Exit criterion: reopen when Turbopack supports an ESLint-compliant ignore for this `node:fs` marker access, or when restore maintenance is moved to a DB/shared-store implementation that removes runtime marker filesystem I/O.
