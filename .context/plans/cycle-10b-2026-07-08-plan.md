### WP-A — Widen the client→server-only boundary test's import-closure walker (AGG-C10b-02, Med/High)

Files: `apps/web/src/__tests__/client-server-only-boundary.test.ts` (loop-B-owned test file;
clean at HEAD).

Problem: `extractAliasedImports`'s edge-follow predicate `isAliased` (line 142) only returns
`true` for `@/lib`/`@/db` specifiers, so the DFS never visits an intermediate `@/components/*`
module. A future `'use client'` file that value-imports `@/components/nav` (a plain Server
Component that already reaches `@/lib/data` → `@/db` → `mysql2`) or one of those components
turning interactive would pass this fast test green and regress to the opaque `next build`
mysql2-bundling failure the test exists to convert into a readable vitest failure.

Steps:
1. Widen `isAliased` (line 142) so the DFS also follows `@/components` value edges (and `@/app`
   if any intra-`@/app` value cross-imports exist). Keep the existing type-vs-value AST
   classification (`import type` / all-`type` named specifiers stay erased) so a client
   component's *type-only* import of a component is still correctly dropped — this is what
   prevents the false-positive class the architect flagged.
2. Confirm `resolveAliasedModule` can resolve a `@/components/*` specifier to its on-disk
   `.tsx`/`.ts` path (the `@/` → `src/` mapping should already generalize; extend only if it
   is hard-coded to `lib`/`db`).
3. Add a self-check assertion in the test's existing does-flag/does-not-flag block: a synthetic
   `'use client'` source string that value-imports `@/components/nav` must be detected as
   reaching server-only (proves the walker now traverses the component edge), while a
   `import type { X } from '@/components/nav'` must NOT (proves type-only stays erased).
4. Run the widened suite — it MUST stay green against the current codebase (architect confirmed
   no live violation). If it goes RED, that is a real latent leak: stop, record it as a new
   HIGH finding, and fix the leak instead of the test.

Acceptance: `npm test --workspace=apps/web -- --run src/__tests__/client-server-only-boundary.test.ts`
green; the new synthetic assertions prove component-edge traversal.

### WP-D — Fix the dormant `archiveRange()` December off-by-one (AGG-C10b-06, Low/High-conf)

Files: `apps/web/src/lib/data-timeline.ts` (clean at HEAD), test in
`apps/web/src/__tests__/data-timeline.test.ts` (or a focused sibling).

Problem: `data-timeline.ts:96` — `const endMonth = month === undefined ? 1 : month + 1;` omits
the `month === 12` wrap that `endYear` (line 95) handles, so `archiveRange(2025, 12)` yields
`end = "2026-13-01 00:00:00"` (invalid MySQL DATETIME). Unreachable today (no caller passes
`month`), but a latent landmine for any future per-month archive view.

Steps:
1. `const endMonth = month === undefined || month === 12 ? 1 : month + 1;`.
2. Add a unit test asserting `archiveRange(2025, 12)` returns `end: '2026-01-01 00:00:00'`
   (and `archiveRange(2025, 6)` → `end: '2025-07-01 00:00:00'`, `archiveRange(2025)` year-only
   → `end: '2026-01-01 00:00:00'`), pinning the range values so the wrap can't regress.

Acceptance: `npm test --workspace=apps/web -- --run src/__tests__/data-timeline` green with the
new December-wrap assertion.
