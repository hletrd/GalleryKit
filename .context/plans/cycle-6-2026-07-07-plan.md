## Work Packages

### WP1 — Close the DB-restore SQL scanner intra-keyword chunk-boundary evasion  (C6-01, MED/High, SECURITY — not deferrable)

- Files: `apps/web/src/lib/sql-restore-scan.ts`, `apps/web/src/app/[locale]/admin/db-actions.ts`,
  `apps/web/src/__tests__/sql-restore-scan.test.ts`.
- Plan:
  1. In `appendSqlScanChunk`, keep the compacted `\n`-join (needed for the >window whitespace
     inter-token case) AND add a byte-continuous RAW overlap bridge: retain the last
     `SQL_SCAN_RAW_BRIDGE_BYTES` (128) raw chars of each chunk, and additionally scan
     `previousRawSuffix + chunkPrefix` (no separator) so a keyword split exactly at the read
     boundary (`DROP TAB`|`LE`) is losslessly rejoined. Return `nextRawSuffix`; thread it from the
     `db-actions.ts` scan loop (backward-compatible optional 4th param so existing 2-arg callers
     are unaffected → bridge disabled when no raw suffix supplied).
  2. Regression test: split dangerous keywords INSIDE the token (`DROP TAB|LE`, `DATABA|SE`,
     `TRIG|GER`, `DELETE F|ROM`, `GLOB|AL`) across the chunk boundary and assert the streamed scan
     returns detected; keep the existing whitespace-boundary cases green.
- Gate: `npm test` (sql-restore-scan suite), typecheck.

### WP2 — Bound the restore background-write drain + document the drain invariant  (C6-03 a+b, MED/High, availability)

- Files: `apps/web/src/lib/background-db-writes.ts`, `apps/web/src/app/[locale]/admin/db-actions.ts`,
  `apps/web/src/__tests__/background-db-writes.test.ts`.
- Plan:
  1. Replace the bare alias with a bounded `drainBackgroundDbWritesForRestore(timeoutMs = 15_000):
     Promise<boolean>` that `Promise.race`s the drain against an unref'd timer (mirrors the
     graceful-shutdown 15s budget for the SAME function; the alias is used ONLY by the restore path,
     instrumentation uses the un-aliased `drainBackgroundDbWrites`). Returns `true` on drain,
     `false` on timeout; clears the timer in `finally`.
  2. In `db-actions.ts` restore prep, check the boolean and ABORT (`return restoreFailed`) on
     timeout — identical to the sibling maintenance/mutation drains; the outer `finally` already
     releases every advisory lock + ends the durable marker + resumes the queue.
  3. Add a comment block at the restore drain sequence enumerating the invariant "every
     process-local DB writer must be drained here" (cheap half of critic F1's registry idea).
  4. Test: a never-settling tracked write + `drainBackgroundDbWritesForRestore(50)` resolves `false`;
     release the write in cleanup so it does not leak into other tests.
- Gate: `npm test` (background-db-writes suite), typecheck.
